## Features

- **The worklog can now be read as a calendar.** A Calendar view sits beside the existing Overview and draws every logged entry on a time axis, one row per person per day. Entries that collide are stacked and marked, and the unlogged stretches between them are hatched, so a day where the records do not follow on is obvious at a glance.

- The axis fits the work rather than the clock: it spans an hour either side of the earliest and latest entry in the whole report instead of an empty 24 hours. It zooms from 1x to 6x with the buttons, a trackpad pinch or ctrl and the wheel, down to a fifteen-minute grid.

- A **People** picker narrows the calendar to whoever you are checking. Overlaps are only ever counted inside one person's own entries, so two people working at the same time is never reported as a conflict.

- Statuses in import filter conditions are now **grouped by the project they belong to**. A Jira site where several projects each define their own workflow could offer four different statuses all named *Done*, listed as four identical rows with no way to tell them apart. Each one now sits under the name of the project that uses it.

- Statuses shared by several projects are collected under a single **Shared across projects** heading instead of being repeated beneath every project, so the list stays short on sites where most projects use the same workflow.

- **Import filter conditions can be reordered.** A condition could only ever be added to the end, so putting a rule first meant deleting everything after it and typing it again. Every condition and group now has up and down arrows. The AND/OR pattern stays where it is while a condition moves through it, so rearranging the rules does not quietly reshape the expression.

- Where a status name occurs more than once, the owning project is shown beside it — in the list, on the closed picker, and in the rule summary printed under the filter. Names that occur only once are left as they are.

## Fixes

- **The worklog filters keep their height when the calendar opens.** Switching to the calendar stretched the filter bar above the results, and a taller window stretched it further. It now stays exactly as tall as it is in the overview.

- **A failed Jira call now says what is wrong.** Instead of *Jira request failed with status 401* beside a *Try again* button, a rejected service account, a missing permission or a missing issue each explain themselves and point at whoever can fix them. Retrying cannot help with any of those, so the button is no longer offered for them — it stays where it belongs, on rate limits and outages.

- **A failed search in the worklog is no longer reported as an empty one.** Searching for a person while the Jira connection was broken answered *No people or groups found*, which sends you hunting for a spelling mistake instead of checking the integration. Both the people and the issue search now show the actual reason. A search that genuinely matches nothing still says so.

- **The *Evaluates as* line no longer misreads a mixed rule.** Conditions are checked strictly from left to right, so *A OR B AND C* means *(A OR B) AND C* — but the line printed it flat, and read with the usual precedence it says something else entirely. There are combinations where the two disagree about whether an issue is imported. Mixed rules are now shown with the brackets the importer actually applies.

- **A signed-out service account is recognised even when Jira hides it.** Jira answers some requests from an account with bad credentials as if it were an anonymous visitor — an empty list and no error at all. Statuses, issue link types and worklog searches could therefore look merely empty while nothing was reaching Jira. An empty result is now verified before it is believed.

## Improvements

- Picking the wrong copy of a duplicated status used to produce a filter that matched nothing, without any hint as to why: conditions are matched by the status identifier, not by its name. The copies are now distinguishable before the choice is made.

- Working out which project owns a status is best effort. On very large sites, or when Jira does not answer, the picker falls back to the plain unsorted list rather than failing — the filter editor always opens.

- Existing saved filters are unaffected. Only the way statuses are presented has changed; what a stored condition matches has not.

- The AND/OR selector no longer occupies a line of its own. It sits in a narrow strip beside its condition together with the reorder arrows, which roughly halves the height of a rule and keeps the controls still when a condition wraps in the narrow queue panel.

- A long date range scrolls inside the calendar instead of stretching the page, so the screen keeps the same shape whatever the report contains.

- The issue search field in the worklog had a Czech placeholder in an otherwise English screen.
