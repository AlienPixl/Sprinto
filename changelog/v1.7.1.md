## Features

- Jira import rules can now filter issues by **labels**. The new condition offers `IN` / `NOT IN` and a multi-select of one or more labels, and is available both in a room's Import from Jira panel and in Settings → Integrations → Jira as part of the default import filters. Labels combine with the existing Story Points, Original Estimate and Status conditions through the usual AND/OR connectors.
- The label list is loaded live from Jira and refreshed every time the picker is opened, so it reflects the current state of the Jira instance without reopening the settings section.

## Known Behaviour

- Jira maintains its list of labels asynchronously in a search index that is updated in the background. A label that has just been created in Jira may therefore be missing from the picker for a while and will appear on its own once Jira has finished indexing it. This delay comes from Jira and is not caused by Sprinto — filtering itself always evaluates the labels stored directly on each issue, so an already-selected label filters correctly even while the index is catching up.
- If the label list cannot be loaded at all, the picker now shows the reason returned by Jira instead of an empty list, which makes a failed connection distinguishable from a Jira instance that genuinely has no labels.
